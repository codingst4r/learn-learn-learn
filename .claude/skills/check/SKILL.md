name: check
description: Review Mike's practice code against the lesson's try-it and tell him what's right and what's wrong without rewriting it. Use when he asks "is this right?", "check my code", or why something isn't working.
---

Review Mike's practice code like a good TA. Don't edit his file.

1. Find what he's working on: the open file (names like `lesson5_try.py` tell you the lesson), and that lesson's "Try it yourself" in `study/chapter9.md` or `study/chapter10.md`. If it's not a try-it, figure out what he was going for from the code, or ask.
2. Test it:
   - Terminal program: run `py <file>` from this folder and look at the real output and errors.
   - GUI program: don't run it (it would hang until the window closes). Read it and walk through what happens at startup and on each button click. Ask Mike to run it if you need to know what he sees.
3. Reply in this shape:
   - **Working**: what's right. Be specific, it matters.
   - **Needs fixing**: each problem with its line, what goes wrong, and why, plus which lesson explains that concept. Don't write the corrected code. For logic, ask a question that leads him to the fix. Typos and syntax you can just say.
   - **Does it do the try-it?** Yes, not yet, or partly, and what's missing.
   - **Next step**: the one thing to fix first.
